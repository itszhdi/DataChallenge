# Freedom CQA — оценка качества диалогов

Прототип Conversation Quality Analytics для хакатона Freedom Broker.

| | |
|---|---|
| Команда | `Cyberpsychosis` |
| Участники | `Быстрицкий Трофим`, `Оспан Диас`, `Жакупбекова Диана` |

## Быстрый старт

### Что нужно

| Компонент | Версия |
|---|---|
| Docker + Docker Compose | любой актуальный (рекомендуемый способ) |
| или Python + [uv](https://docs.astral.sh/uv/) | Python 3.15+ |
| Node.js | 20+ (нужен только для разработки фронтенда; готовый интерфейс уже собран) |
| LLM | ключ Gemini API **или** локальная модель в Ollama / LM Studio |

### 1. Настройка бэкенда

```bash
cd backend
cp .env.example .env
```

В `backend/.env` укажите:

- `DATASET_API_URL` — ссылка организаторов **без** `&group_id` в конце (бэкенд дописывает его сам);
- для облачной модели: `LLM_API_KEY`, `LLM_MODEL`;
- для локальной модели: `LOCAL_LLM_BASE_URL`, `LOCAL_LLM_MODEL`.

### 2. Запуск бэкенда

**Docker (рекомендуется):**

```bash
cd backend
make docker-up            # облачная модель или LM Studio
make docker-up-ollama     # локальная модель в Ollama на Linux (контейнер в сети хоста)
```

**Без Docker:**

```bash
cd backend
make install              # uv sync
make run                  # http://localhost:8000
```

Проверка: `curl localhost:8000/api/health` возвращает активный профиль и модель.

### 3. Интерфейс

**Готовый файл, без Node и сервера.** Откройте двойным кликом `frontend/build/index.html`. Весь интерфейс собран в этот один файл: JS, CSS, шрифты, логотипы.

- Бэкенд на `localhost:8000` подхватывается автоматически.
- Бэкенд на другом адресе: `frontend/build/index.html?api=http://адрес:порт/api`.

### 4. Первые данные

В интерфейсе: «Диалоги» → «Импорт» → `group_id` = `DEV`. Из терминала то же самое делает `make import-dev`.

## Модели

Есть два профиля. Активный выбирается в «Настройках» или командами `make use-gemini` / `make use-local`. `make models` проверяет доступность обоих профилей.

| Профиль | Режим в выгрузке | Описание |
|---|---|---|
|  | `external_api` |  |
| `local` | `local` | Ollama или LM Studio на этой же машине |

Если оценки сделаны разными профилями, в выгрузке указывается `hybrid` и перечисляются все модели.

### Локальная модель: Ollama

```bash
ollama pull qwen2.5:7b
printf 'FROM qwen2.5:7b\nPARAMETER num_ctx 16384\n' > Modelfile
ollama create qwen2.5:7b-cqa -f Modelfile
```

В `backend/.env`:

```env
LOCAL_LLM_BASE_URL=http://localhost:11434/v1
LOCAL_LLM_MODEL=qwen2.5:7b-cqa
LOCAL_LLM_API_KEY=ollama
LOCAL_LLM_TIMEOUT_SEC=600
```

Запуск: `make docker-up-ollama`, затем в настройках выберите локальную модель. Ollama слушает только `127.0.0.1`, поэтому контейнеру нужна сеть хоста.

### Локальная модель: LM Studio

```bash
lms get qwen/qwen3.5-9b@q4_k_m
lms server start
lms load qwen/qwen3.5-9b --context-length 16384 --parallel 1
```

### Облачная модель

Укажите `LLM_API_KEY` и `LLM_MODEL` в `backend/.env`. Пауза между запросами задаётся в `LLM_MIN_INTERVAL_SEC` или в настройках интерфейса.

## Как пользоваться

1. **Диалоги** → «Импорт»: укажите `group_id`, ссылку или JSON-файл.
2. «Оценить неоценённые» — пакетная оценка в фоне с прогрессом. Кнопка «Оценить» в строке оценивает один диалог.
3. Откройте диалог. Для каждого критерия видны ответ, балл, вес, объяснение и ссылки `#N` на реплики. Клик по ссылке прокручивает транскрипт, а в звонке перематывает запись.
4. **Апелляция:** «Оспорить» у критерия → комментарий → сохранить.
5. **Решение:** в том же критерии проверяющий подтверждает или меняет оценку и пишет причину. Итог пересчитывается, исходная оценка остаётся видна.
6. **Настройки:**
   - чек-лист (критерии, веса, шкалы, N/A) с кнопкой «Применить к диалогам»;
   - профиль модели, источник транскрипта звонков;
   - порядок очереди, потоки, задержка;
   - автооценка после импорта, авторежим, `group_id` по умолчанию.
7. **Общий отчёт:** KPI, графики и проблемные диалоги. Клик по графику фильтрует список.
